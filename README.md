# Coloring Elements

[사용 설명서](docs/USER_GUIDE.md) · [변경 이력](CHANGELOG.md) · [릴리즈 / VSIX 다운로드](https://github.com/ynaru1203/coloring-elements/releases) · [개발 안내](docs/DEVELOPMENT.md)

**C# 코드 색상을 JSON 편집 없이 바꾸는 VS Code 확장입니다.** 필드·프로퍼티·함수 등의 종류와 접근 범위, `readonly`, `private set`, get 전용 같은 조건을 GUI에서 선택합니다. 키워드와 `true`·`false`·`null`도 각각 다른 색상으로 설정할 수 있습니다.

기존 테마와 Microsoft C# 확장을 유지하면서, 지정한 요소의 색상만 변경합니다. 한국어 항목명과 설명을 제공하며 HEX·RGB 입력과 색상 선택기를 지원합니다.

> 초기 공개 버전입니다. Windows와 일반 C# 테스트 프로젝트에서 검증했으며, 실제 Unity 대형 솔루션과 Remote/WSL 환경은 추가 확인이 필요합니다.

## 설치

1. [최신 릴리즈](https://github.com/ynaru1203/coloring-elements/releases/latest)에서 `.vsix` 파일을 받습니다.
2. VS Code 명령 팔레트에서 **Extensions: Install from VSIX...**를 실행합니다.
3. 설치 후 **Developer: Reload Window**를 실행합니다.

VS Code **1.140.0 이상**이 필요합니다. 정밀 분류에는 PATH에서 실행 가능한 **.NET 10 SDK**, C# 솔루션/프로젝트와 그 프로젝트에 필요한 참조·타깃 팩이 필요합니다. 기본 분류는 기존 C# 언어 서버가 제공하는 정보를 사용합니다.

## 시작하기

1. C# 프로젝트 폴더를 열고 코드 편집기에서 우클릭 → **Coloring Elements: C# 색상 편집기 열기**를 선택합니다.
2. **정밀 분류 (Roslyn)**에서 **분석할 솔루션·프로젝트 선택**으로 `.sln`, `.slnx` 또는 `.csproj`를 불러옵니다.
3. 코드의 이름 안에 커서를 놓고 **선택한 식별자 감지**를 누릅니다. 요소와 해당 속성이 자동 선택됩니다.
4. 필요한 조건만 남긴 뒤 색상을 선택합니다. 체크한 조건을 모두 만족하는 선언과 참조에 적용됩니다.

| 원하는 설정 | 요소 | 조건 또는 종류 |
| --- | --- | --- |
| readonly 필드 | 필드 | 읽기 전용 |
| private set 프로퍼티 | 프로퍼티 | 설정 범위: 선언한 클래스·구조체 안에서 접근 |
| get 전용 프로퍼티 | 프로퍼티 | 읽기만 가능 (get 전용) |
| 함수 이름 | 함수 | 필요한 접근 범위·static 조건 선택 |
| public 예약어 자체 | 키워드 | public |
| true 값 자체 | 고정값 | 참 (true) |

키워드·고정값의 종류 드롭다운은 해당 요소에서만 표시합니다. 필드·프로퍼티 등에서는 속성 조합을 표시하고, 기본 분류에서는 속성 조합을 표시하지 않습니다.

## 두 가지 분류 방식

| | 기본 분류 | 정밀 분류 |
| --- | --- | --- |
| 분류 정보 | 기존 C# 언어 서버의 Semantic Token | 선택한 프로젝트의 Roslyn 의미 분석 |
| 설정 단위 | 서버가 제공한 요소 종류 | 심볼 종류·속성 조합·키워드·고정값 종류 |
| 색상 적용 | VS Code 네이티브 색상 규칙 | 기존 강조 위에 색상 장식 적용 |
| 추가 SDK | 서버에 필요한 환경 | .NET 10 SDK와 프로젝트 참조 필요 |

서버가 제공하지 않은 속성을 기본 분류에서 지원한다고 가정하지 않습니다. 정밀 분류는 기존 C# provider를 교체하지 않습니다.

## 저장·초기화

사용자 또는 작업 공간 범위를 선택할 수 있습니다. 색상 선택기를 드래그하는 동안에는 숫자만 갱신하고, 선택 확정 시 한 번 저장합니다. HEX·RGB는 Enter 또는 포커스 이동 시 저장합니다.

초기화는 **현재 범위의 해당 규칙 색상 제거**입니다. 상위 범위나 다른 규칙이 남으면 상속합니다. 선택기·HEX·RGB도 상속된 색상으로 갱신하지만, 복잡한 테마의 미리보기는 실제 화면과 다를 수 있습니다. 가져오기·내보내기는 현재 분류 방식의 색상 규칙을 병합하며 같은 조건의 색상은 덮어씁니다.

## 지원 범위와 제한

- 정밀 분류는 필드/프로퍼티 구분, 접근 제한자, `static`, 필드 `readonly`, `const`, get 전용, init 전용, 접근자별 범위를 지원합니다.
- 같은 심볼의 참조에도 같은 속성을 적용하고, 열린 C# 파일의 미저장 수정 내용을 반영합니다.
- 키워드는 Roslyn의 실제 분류를 사용합니다. 주석·문자열과 `@class` 같은 식별자를 키워드로 칠하지 않습니다.
- 프로젝트 컴파일 오류, 참조 누락, 모호한 프로젝트 문맥이 있으면 정밀 색상을 보류하고 기존 강조를 유지합니다.
- 전처리 지시문, 비활성 코드, 임의 숫자/문자열 내용별 선택, 인덱서의 `this` 등 특수 표시는 지원 범위에 포함하지 않았습니다.
- 정밀 분석은 신뢰한 작업 공간에서만 실행합니다. 확장이 프로젝트 복원이나 실제 빌드를 자동 수행하지는 않습니다.

자세한 조작과 문제 해결은 [사용 설명서](docs/USER_GUIDE.md), 구현과 검증 범위는 [아키텍처](docs/architecture.md)와 [검증 기록](docs/verification.md)을 확인하세요.

```sh
npm test
npm run package
```

개발에는 Node.js/npm과 .NET 10 SDK가 필요합니다. 환경 설정·F5 디버깅·검증 방법은 [개발 안내](docs/DEVELOPMENT.md)에 있습니다. 버그를 보고할 때는 [Issues](https://github.com/ynaru1203/coloring-elements/issues)에 오류 메시지, VS Code/.NET/Unity 버전과 최소 재현 코드를 남겨 주세요. 개인 정보나 비공개 프로젝트 전체는 첨부하지 마세요.
