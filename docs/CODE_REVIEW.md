# 코드 정리 기록

기준: 0.2.1, 2026-10-28.

## 주석 처리한 코드

| 위치 | 확인 내용 | 처리 |
| --- | --- | --- |
| src/rules.ts의 modifiers export | 기본 분류의 속성 조합 UI 제거 후 import/참조가 없음 | 원래 목록과 이유를 주석으로 보존 |
| src/extension.ts의 빈 deactivate 함수 | 본문이 없으며 종료 정리는 context.subscriptions의 Disposable에서 수행 | 빈 함수와 이유를 주석으로 보존 |

요청에 따라 삭제 대신 주석 처리했습니다. 작동 중인 기능과 저장된 사용자 규칙은 제거하지 않았습니다.

## 유지한 경로

- `activate`: 정적 호출 참조는 없어도 VS Code가 manifest의 main 진입점으로 직접 호출합니다.
- Webview의 이벤트 핸들러와 호스트 메시지 분기: HTML 컨트롤·메시지로 도달하는 실제 실행 경로입니다.
- `--server`, `--catalog`, `--self-test`: 분석기 실행, 종류 목록 검증, 자체 테스트에서 사용합니다.
- C# fixture의 필드와 프로퍼티: 이름 가리기·접근자·키워드 분류를 검증하는 테스트 데이터입니다.
- 한국어 속성 설명: 정밀 체크박스뿐 아니라 감지 결과와 이전 기본 규칙의 표시에도 사용합니다.
- 오류 처리·타임아웃·문서 버전 확인·프로세스 종료: 실패 시 잘못된 색상이나 오래된 결과를 적용하지 않기 위한 동작입니다.

## 점검 방법과 한계

`tsc --noEmit --noUnusedLocals --noUnusedParameters` 검사와 TypeScript language service의 export 참조 조회를 사용하고, 호출부·manifest·HTML/JavaScript·C# 분기를 대조했습니다. C# 빌드 경고를 오류로 처리하는 설정과 전체 테스트도 유지합니다.

이 점검은 모든 런타임 경우의 도달 가능성을 수학적으로 증명하는 분석은 아닙니다. 확인할 수 없는 코드나 간헐적으로 쓰이는 복구 경로를 미사용으로 단정해 주석 처리하지 않았습니다.

프로젝트 생성기의 Hello World 안내 문서는 실제 [개발 안내](DEVELOPMENT.md)로 교체하고, 오래된 진행 기록을 현재 아키텍처·사용 설명서·검증 기록으로 정리했습니다.
