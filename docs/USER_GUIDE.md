# 사용 설명서

[README](../README.md) · [변경 이력](../CHANGELOG.md) · [릴리즈](https://github.com/ynaru1203/coloring-elements/releases)

## 1. 설치와 준비

[릴리즈](https://github.com/ynaru1203/coloring-elements/releases/latest)에서 VSIX를 받아 VS Code의 **Extensions: Install from VSIX...**로 설치합니다. 업데이트 후에는 **Developer: Reload Window**를 실행합니다. Marketplace에는 게시하지 않은 로컬 VSIX 배포입니다.

기본 분류를 사용하려면 Microsoft C# 등 Semantic Token을 제공하는 C# 언어 서버가 준비되어 있어야 합니다. 정밀 분류는 별도 Roslyn 분석기를 실행하며 .NET 10 SDK와 선택한 프로젝트의 참조/타깃 팩이 필요합니다. 터미널에서 `dotnet --list-sdks`로 설치된 SDK를 확인할 수 있습니다.

Unity에서는 IDE 연동 기능으로 솔루션·프로젝트 파일을 생성하고 해당 프로젝트 폴더를 VS Code에서 엽니다. 이 확장이 Unity 프로젝트 파일을 생성하거나 참조 패키지를 자동 설치하지는 않습니다.

## 2. 편집기 열기

C# 파일에서 우클릭하여 **Coloring Elements: C# 색상 편집기 열기**를 실행하거나 명령 팔레트에서 같은 명령을 찾습니다. 옆에 열린 색상 편집기는 마지막으로 활성화한 C# 편집기를 대상으로 감지합니다.

- **분류 방식**: 기본 분류와 정밀 분류를 선택합니다. 두 방식의 색상 규칙은 별도 저장됩니다.
- **저장 범위**: 사용자는 여러 프로젝트에서 사용하는 설정, 작업 공간은 현재 작업 공간 설정입니다.
- **요소**: 클래스·함수·필드·프로퍼티 등 색상을 지정할 대상을 고릅니다.

## 3. 정밀 분류

**분석할 솔루션·프로젝트 선택**에서 `.sln`, `.slnx`, `.csproj`를 고릅니다. 프로젝트가 하나뿐이면 자동 선택할 수 있습니다. 선택은 작업 공간에 기억되며 다음 실행에도 사용됩니다.

코드의 식별자 내부에 커서를 놓고 **선택한 식별자 감지**를 누르면 종류와 실제 속성이 선택됩니다. 감지는 색상을 자동 저장하지 않습니다. 감지된 조건 중 원하는 조건만 남기고 색상을 바꾸세요. 체크박스는 OR가 아니라 **모두 만족(AND)** 조건입니다.

### 필드와 프로퍼티 예시

```csharp
private readonly int id;
private int count;
public int Health { get; set; }
public int MaxHealth { get; private set; }
public int Level { get; }
public int Initial { get; init; }
```

| 대상 | 요소와 주요 조건 |
| --- | --- |
| id | 필드 + 읽기 전용 + 필요한 접근 범위 |
| count | 필드 + 선언한 클래스·구조체 안에서 접근 |
| MaxHealth | 프로퍼티 + 설정 범위가 private |
| Level | 프로퍼티 + 읽기만 가능 (get 전용) |
| Initial | 프로퍼티 + 초기화할 때만 설정 가능 |

`readonly` 필드는 다른 값으로 다시 대입할 수 없다는 뜻입니다. List 등의 내용까지 변경 불가능하다는 의미는 아닙니다. get 전용과 private set 역시 서로 다른 성질이며 readonly 필드로 취급하지 않습니다.

‘읽기/설정 기능 있음’과 각각의 접근 범위를 조합할 수도 있습니다. 상충하는 조건(예: public과 private를 동시에 체크)은 매칭되는 요소가 없습니다. 항목 위에 마우스를 올리면 한국어 설명을 볼 수 있습니다.

### 키워드와 고정값

- 요소 **키워드 (예약어)** → 종류에서 `public`, `private`, `class`, `struct`, `readonly`, `get`, `set`, `var` 등을 고릅니다.
- 요소 **고정값 (true·false·null)** → 참(true), 거짓(false), 값 없음(null)을 고릅니다.
- ‘모든 키워드’ 또는 ‘모든 고정값’을 먼저 지정하고 개별 종류의 색상으로 덮어쓸 수 있습니다.

종류 드롭다운은 이 두 요소에서만 표시합니다. 이때 심볼 속성 체크박스는 숨깁니다. 키워드나 고정값에 커서를 놓고 감지하면 그 종류가 자동 선택됩니다.

`public` 접근 조건은 해당 심볼의 성질을 뜻하고, 키워드 종류의 `public`은 코드에 적힌 예약어 자체입니다. 예를 들어 `public int Health`에서 함수/프로퍼티 이름과 `public` 단어의 색상은 별도로 설정합니다.

문자열과 주석 속 단어, `@class` 같은 이름, 식별자로 쓰인 `var`는 해당 키워드 규칙으로 칠하지 않습니다. 키워드 목록은 포함된 Roslyn 5.0.0 기준입니다. 전처리 지시문·비활성 코드는 이번 범위에 포함하지 않습니다.

### 우선순위

정밀 규칙은 다음 순서로 정합니다.

1. 체크한 조건 또는 종류를 더 많이 지정한 규칙
2. 조건 수가 같으면 ‘모든 요소’보다 특정 요소를 지정한 규칙
3. 그래도 같으면 규칙 ID의 사전순

감지 결과에 현재 적용되는 정밀 규칙을 표시합니다. 지정한 정밀 규칙이 없으면 기존 강조를 유지합니다. 화면에 보이는 파일을 열 때마다 그 파일의 선언과 참조를 분석합니다. 편집 중에는 이전 장식을 지우고 새 분석 결과가 준비되면 다시 적용합니다.

## 4. 기본 분류

기존 C# 언어 서버가 제공한 요소 종류에 네이티브 색상 규칙을 적용합니다. 속성 조합 UI는 표시하지 않으며, 새 요소 선택과 감지는 요소별 규칙을 편집합니다.

이전 버전에서 저장한 속성 규칙은 삭제하지 않습니다. 저장된 규칙 목록에서 해당 항목을 클릭하면 같은 규칙의 색상을 바꾸거나 초기화할 수 있습니다. 새로운 속성 조합은 정밀 분류를 사용하세요.

서버가 필드와 프로퍼티를 같은 타입으로 반환하거나 readonly를 누락하면 기본 분류로는 분리할 수 없습니다. 의미 강조가 꺼져 있으면 **C# 의미 강조 켜기**를 누르세요.

## 5. 색상 입력과 저장

색상 선택기는 드래그 중 숫자만 갱신하고 브라우저의 선택 확정(change) 시 한 번 저장합니다. HEX는 `#RRGGBB`, RGB는 `0~255` 정수 세 개를 쉼표로 입력합니다. HEX/RGB는 Enter 또는 포커스 이동 시 저장됩니다.

초기화는 선택한 저장 범위의 해당 색상 규칙을 제거합니다. 설치 전 색상으로 복구하는 기능이 아닙니다. 상위 범위나 더 구체적인 규칙이 있으면 그것을 상속합니다. 선택기·HEX·RGB도 갱신하지만 테마 미리보기는 추정값일 수 있습니다. 확인할 수 없는 색상은 기존 숫자를 지웁니다.

**VS Code 적용 색상 검사**는 네이티브 분류 검사기입니다. 정밀 장식의 승자 규칙은 확장의 감지 결과에서 확인해야 합니다.

## 6. 가져오기·내보내기와 제거

가져오기/내보내기는 현재 저장 범위와 분류 방식의 일반 색상 규칙을 처리합니다. 가져오기는 병합이며 같은 선택자의 색상은 덮어씁니다. 글꼴 스타일이나 테마별 블록 전체를 복사하지 않습니다. 변경 전에 내보내기를 해 두면 이전 색상을 다시 가져올 수 있습니다.

기본 분류와 정밀 분류 파일은 서로 다른 방식으로 가져올 수 없습니다. 이전 버전의 engine 항목 없는 파일은 기본 분류에서 가져옵니다.

기본 규칙은 `editor.semanticTokenColorCustomizations`, 정밀 규칙은 `coloringElements.rules`에 저장됩니다. 직접 JSON을 편집할 필요는 없습니다. 확장 제거 후에도 설정 값은 남습니다. 네이티브 규칙은 VS Code가 계속 적용하고, 정밀 규칙은 확장이 꺼지면 장식이 제거되어 적용되지 않습니다.

## 7. 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| dotnet 실행 실패 | .NET 10 SDK 설치와 PATH 확인 후 VS Code 다시 시작 |
| 프로젝트를 찾지 못함 | Unity 프로젝트 파일 생성 여부, 현재 폴더, 선택한 csproj 확인 |
| 컴파일 오류로 정밀 적용 보류 | 표시된 컴파일 오류와 참조/타깃 팩 문제를 먼저 해결 |
| 여러 프로젝트에 포함된 파일 | 솔루션 대신 분석할 문맥의 csproj 선택 |
| 기본 분류의 색상이 바뀌지 않음 | C# 서버 준비·의미 강조·더 구체적인 기존 규칙·테마별 규칙 확인 |
| 초기화 후 색상이 남음 | 사용자/작업 공간 범위 및 다른 규칙의 상속 확인 |
| 저장한 색상과 미리보기가 다름 | 복잡한 테마의 미리보기 한계와 정밀 승자 규칙 확인 |

프로젝트 복원/빌드는 사용자의 개발 도구로 수행합니다. 확장은 실패 상태에서 색상을 추측하지 않습니다. 신뢰하지 않은 작업 공간에서는 정밀 분석기를 시작하지 않습니다.

Untitled 문서, 프로젝트 밖의 파일, 일부 특수 구문과 실제 Unity 대형 솔루션/Remote 환경에는 제한이 있습니다. 버그를 보고할 때는 오류 메시지와 버전, 비공개 내용을 제거한 최소 재현 코드를 [Issues](https://github.com/ynaru1203/coloring-elements/issues)에 남겨 주세요.
